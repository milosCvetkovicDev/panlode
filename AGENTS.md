# Agent instructions

This repository ships a Claude Code workspace template (`template/`), its installer (`install.sh`), a
Claude Code plugin that runs the installer (`.claude-plugin/`, `plugin/skills/`), a real example run
(`examples/`) and a documentation site (`docs/`). Read `CONTRIBUTING.md` for the ground
rules; the ones agents break most often are repeated here.

## Commands

```bash
cd template && python3 -I -m unittest discover -s scripts/tests -t scripts && cd ..   # engine
python3 -m unittest discover -s tests -t .                                            # repository
bash install.sh --dry-run /tmp/<unique-name>                                           # installer plan
claude plugin validate .                                                               # plugin manifests
```

All of them must pass before a change is done. CI runs the two test suites on Python 3.10 to 3.15 (Linux)
and 3.14 (macOS), then installs into an empty folder and runs `check` and `brief` there; it does not
run `claude plugin validate`, so run that yourself when you touch `.claude-plugin/` or `plugin/`.

## Rules

- Standard library only, Python 3.10+. No third-party imports anywhere.
- Tests first: a failing test, then the change. Never weaken or delete a test to get to green.
- `install.sh` runs on bash 3.2 (macOS): no `mapfile`, associative arrays or `${var,,}`.
- `template/` is what users receive. Keep it free of machine paths (`/Users/`, `/home/`,
  `/usr/local/bin`) and of anyone's personal data; `tests/test_repo.py` checks the paths.
- `INDEX.md` files are generated by `engine.py index`; never edit them by hand.
- The plugin ships no hooks, agents, commands or MCP servers: workspace hooks refuse product code and
  would break every other project if enabled globally. `tests/test_plugin.py` checks this.
- `.github/assets/demo.svg` is generated from real engine runs by `.github/assets/src/make_demo.py`;
  the PNG assets by `.github/assets/src/render.sh`. Regenerate, never hand-edit.
- The hook names (`session-start`, `pre-write`, `post-write`, `stop`) and the guard in front of each hook
  command are a public interface: installed workspaces keep their `.claude/settings.json`, so never rename
  a hook or remove the guard.
- The version lives in `.claude-plugin/plugin.json` and needs a matching `CHANGELOG.md` section.
- Example signals are real records. Never invent URLs, companies, quotes or numbers.
- Docs claims must match the code: when you change a command, a limit or a hook, update `README.md` and
  `docs/` in the same change.
